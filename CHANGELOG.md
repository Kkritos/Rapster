# Changelog

All notable changes to Rapster will be documented in this file.

## [2.16.0] - 2026-10-29

Faster for compact clusters, with statistically equivalent results. Three changes use the random numbers differently (below), so a given seed can give another realization than 2.15.1, with the same distributions: in clusters with up to ~1.3e5 single BHs, only time steps with several BH-star TDEs or several GW captures are affected (the default run is identical to 2.15.1 except the last digits of `v_rel` in `tdes.txt`; 24 of the 32 test configurations differ, and all of them run to the end). Validated against 2.15.1 with 600 runs of N = 2e6, r_h = 0.3 pc (numbers of mergers by channel, of TDEs, three-body binaries, GW captures, exchanges and BBH-BBH interactions, final numbers and masses of the BHs, and merger and TDE properties, per run: all within 1.3 standard errors) and 40 runs of the first 20 Myr of N = 1e8, r_h = 0.1 pc (~5e5 TDEs and ~8e4 mergers each, in pools of ~6e5 single BHs: all within 1.7 standard errors) 100 runs of N = 1e7, r_h = 0.32 pc near the threshold for IMBH formation (a BH grows beyond 1e3 Msun in 15% and 18% of the runs, Fisher p = 0.70; largest BH masses KS p = 0.58), and 500 runs of an NS-rich cluster, `-NS 1 -N 2e6 -r 0.3 -Z 0.02` (~21 BNS and ~9.5 NSBH mergers per run: their numbers per channel, masses, merger times, remnants and kicks, and the TDEs by NSs, all within 1.2 standard errors); earlier versions of these changes were also compared on 400 runs of the default cluster and 60 runs of N = 1e7, r_h = 0.1 pc to 400 Myr. Paired timings (the two versions running side by side): vs 2.15.0, 1.9x for the full run of N = 10^7.5, r_h = 0.1 pc (513 -> 267 s; 396 s with 2.15.1), 2.0x for the first 25 Myr of N = 1e8, r_h = 0.1 pc (155 -> 79 s; 1.8x vs 2.15.1), 1.25x for N = 2.5e7, r_h = 0.41 pc to 400 Myr (13.6 -> 10.9 s), 1.4x for a 2e4 Msun seed BH in N = 2e6, r_h = 0.3 pc, n = 4e7 pc^-3 (35.5 -> 25.5 s, as 2.15.1), unchanged for ordinary clusters. Peak memory is unchanged.

### Performance (statistically equivalent results)
- **Pool sums in two levels for large pools** (`bhpool.py`). In pools of more than 1024 blocks (~1.3e5 single BHs, e.g. N = 1e8, r_h = 0.1 pc) the block sums are grouped in superblocks of 64 blocks: a draw locates the random number among the cumulative superblock sums, then among the cumulative block sums of one superblock, then inside one block, and a change of a BH updates the sums of its superblock instead of the cumulative block sums from its block on (O(n/128) per change, which dominated such clusters with ~1e6 TDEs). The sums differ from those of 2.15.1 in the last bits; a draw that falls beyond a sum by rounding is repeated. Smaller pools are drawn as in 2.15.1.
- **TDEs of a time step** (`tidal_disruptions.py`). The BH that disrupts a star is drawn with weights (m_star + m) m^(1/3) at the current masses, which grow with every TDE. The pool is now left unchanged during the TDEs of a step and the BHs that grew are updated at the end: the weights at the current masses are the pool's weights plus, for every TDE so far, the increase of the weight of its BH, so the BH is drawn from the pool or from the TDEs so far in proportion to the two totals (an exact decomposition of the same distribution). The mean single-BH mass in the relative velocity is updated with each TDE as before (the same value up to rounding).
- **GW captures of a time step** (`two_body_capture.py`). The BHs captured in binaries are excluded from the later draws of the step (proposals containing them are rejected, with the probabilities p of the other BHs) and removed at the end of the step, as was already done for three-body binaries; the pool is updated earlier if the heaviest BH is captured or if many proposals hit captured BHs.

### Performance (results unchanged)
- **Background writer** (`arraycache.py`). The rows of the evolution, hardening and TDE tables (millions in compact clusters) are written to their files by a separate process while the simulation continues (chunks of at least 20000 rows, sent in pieces of 10000 rows; the text is the same). Checkpoints and the end of the run wait until every row is written. Set the environment variable `RAPSTER_BACKGROUND_WRITER=0` to write them from the simulation process as before.

### Changed
- **README, Section 8 "Run time and memory"**: the run-time map is redone with this version (one core, background writer off), with the mass of the IMBH where one forms, and the text explains the seed-to-seed scatter of the run time near the threshold for IMBH formation (checked with 100 seeds of N = 1e7, r_h = 0.32 pc: 15% and 18% of the runs grow a BH beyond 1e3 Msun with 2.15.1 and 2.16.0) and when to switch the background writer off.

The new tests are in `tests/test_speedups_2160.py`.

## [2.15.1] - 2026-10-29

Faster, with byte-identical results: every output file is the same as with 2.15.0 for a given seed (32 test configurations up to N = 1e8, including multiple populations, NSs, residual gas and IMBH seeds). Paired timings (the two versions running side by side): 1.30x for the full run of N = 10^7.5, r_h = 0.1 pc (515 -> 396 s), 1.47x for a 2e4 Msun seed BH in N = 2e6, r_h = 0.3 pc, n = 4e7 pc^-3 to 200 Myr (37.9 -> 25.7 s), 1.24x for a 1000 Msun seed BH in the default cluster (9.8 -> 7.9 s), 1.11x for the first 25 Myr of N = 1e8, r_h = 0.1 pc (158 -> 143 s), unchanged for ordinary clusters.

### Performance (results unchanged)
- **Pool of single BHs** (`bhpool.py`): the cumulative block sums used by the weighted draws are brought up to date in one pass from the first changed block, for several weight families at once where they are drawn together (the BBH-single partner and the three-body binaries); a draw locates its block in a list copy of the cumulative sums (`bisect`) and its BH in a cumulative sum of the block's weights kept until the block changes; repeated draws from an unchanged pool use a draw function with these lookups bound (`BHPool.drawer`). The weight families drawn together are stored next to each other (checkpoints of 2.15.0 are converted when loaded). A heavier mass of the heaviest BH no longer triggers a search for the heaviest BH over the whole pool (an IMBH growing by TDEs). Same sums and same draws, bit for bit.
- **Three-body binaries** (`three_body_binary.py`): what the sampler computes from the pool (region totals, draw functions) is kept while the pool is unchanged, i.e. for all the binaries formed between two removals of the BHs taken; the BHs taken are removed in one call.
- **BBH interactions** (`binary_evolution.py`): the loop over interactions uses Python floats for the rates, the GW time and the encounter outcomes (the same IEEE operations as with NumPy scalars; where Python would raise on a division by zero or an overflow, the NumPy value is used), and the triples formed in BBH-BBH interactions are appended to the triple array once per step.
- **Tables of binaries and triples**: a row is deleted by moving the rows after it in place with one memory move, and the binaries released by triples are appended once per step (the same rows in the same order).
- **Mergers**: remnant mass, spin and kick computed in one pass, with the cosines of the spin angles computed once (`merger_remnant`); the redshift of a merger interpolated without the overhead of `scipy.interpolate.interp1d` (the same `np.interp` that `interp1d` calls; with scipy versions that do not use it, `interp1d` is called as before).
- **GW captures and TDEs**: constants computed once per step, and the quantities of a TDE computed on Python floats, which also makes the Euler loop of the spin evolution faster; for the Runge-Kutta spin evolution of BHs, the last mass of the Euler steps it reproduces is computed directly instead of by ~100 additions (within a binade the additions all add the same rounded step; otherwise, or for a step halfway between two representable increments, the additions are done).

The new tests are in `tests/test_speedups_2151.py`.

## [2.15.0] - 2026-10-28

Easier set-ups for users: multiple stellar populations, checkpoints and restarts, and simpler options. For a single stellar population, results are byte-identical to 2.14.3 for a given seed except where fixes 1 and 2 apply and with residual gas (`-sfe` < 1, through the new `-tge`); of 30 test configurations up to N = 1e8, 26 are identical, `-sfe 0.5` changes through `-tge`, one ends a step earlier through fix 1, and two tidally limited clusters change in their last steps before dissolution through fix 2.

### Added
- **Multiple stellar populations** (`-POP pops.txt`, new `rapster/populations.py`; README section "Multiple stellar populations"). Populations born after t = 0, each with its own birth time, number of stars, metallicity and star formation efficiency, and the same IMF, binary fraction and compact-object prescriptions as the first. A population adds its stars (which then age from its birth: mean stellar mass, stellar-evolution mass loss, turn-off mass of the stars drawn in encounters and TDEs, and white-dwarf formation, each at its own age), its residual gas (expelled with the cluster's on `-tge`), its hard stellar binaries, and its BHs and NSs, which form 10 Myr later (NSs as set by `-NSt`) and are retained if their kick is below the escape velocity then. The cluster mass, number of stars, mean stellar mass and central density are sums over the populations; the escaping mass is shared among them; time steps end at each birth and are at most the age of the youngest population. Optionally a population is born segregated, with half-mass radius x times that of the cluster: a central density larger by x^-3 (stars of the center drawn with weight N_k x^-3, central density of the cluster multiplied by sum_k (N_k/N) x_k^-3), escape in proportion to its Plummer mass outside 2 r_h, and mixing of x to 1 on n_mix half-mass relaxation times (default 5). New output `populations.txt` (`-POPi`, `-POPF`): every population at every time step. Until a second population is born the code takes exactly the single-population path (`tests/test_populations.py`).
- **Checkpoints and restarts** (`-CKi`, `-CKdt`, `-RS`, new `rapster/restart.py` and `rapster/join_restart.py`; README section "Checkpoints and restarts"). A run writes `checkpoint.pkl` every `-CKdt` = 500 Myr of simulated time and at the end of a run stopped by `-tM` or `-fCO` (the whole state, including the random-number generator; the table rows that can no longer change are written to their files at the same time, `StreamedRowLog.sync`; ~0.1 s per run, and ~0.4 MB for N = 1e6). `-RS <folder> -RF <new folder>` restarts from it, optionally with a new `-tM`, seed (`-S`), half-mass radius (`-r`), added BHs (`-addBH`), a population born at the restart (`-addN`, `-addZ`, `-addSFE`, `-addx`, `-addnmix`), later populations (`-POP`) or stopping conditions (`-fCO`, `-GC`); other options are refused, as the parameters of the run are those of the checkpoint. The restarted folder holds the rows from the checkpoint on and `restart.json`, and `python -m rapster.join_restart -o OUT RUN RESTART [...]` joins the files. A restart without changes, joined, is byte-identical to an uninterrupted run, also from the `.part` files of a run stopped abruptly and for chains of restarts (`tests/test_restart.py`).
- **`-R 0`**: a cluster at the galactic center (e.g. a nuclear star cluster), without galactic tides (escape rate of an isolated cluster) or dynamical friction. **`-GC 1`**: a cluster that reaches the center by dynamical friction continues there without galactic tides, instead of stopping (`CLUSTER REACHED GALAXY CENTER` stays the outcome by default).
- **`-fCO`**: the maximum mass fraction of compact objects (default 0.2, formerly the fixed `fBH_max`); the stop is reported as `COMPACT OBJECTS REACHED A FRACTION fCO_max = ... OF THE CLUSTER MASS`.

### Changed
- **`-tge` replaces `-fge`**: the gas expulsion timescale is given in Myr (default 10 Myr) instead of in units of the initial crossing time (default 5, i.e. ~0.2 Myr for N = 1e6, r_h = 1 pc and `-sfe 0.5`). Runs with residual gas (`-sfe` < 1) change accordingly.

### Fixed
1. **Compact-object fraction** (`run_cluster.py`). The stop at a fraction 0.2 of the cluster mass counted only single BHs (and NSs); the compact objects in BBHs, hierarchical triples and BH-star pairs are now counted too (`compact_object_mass` in `cluster_evolution.py`), so a run can stop a little earlier.
2. **Escape-limited time step** (`compute_timescales`). A tidally filling cluster near dissolution has a large escape rate xi_e (it grows as exp(10 r_h/r_J)), and a step of up to 50 Myr could remove most of its mass at once: the half-mass radius could become negative (giving `nan` from then on), or the cluster could be reported dissolved from a sizeable mass in one step. Time steps now remove at most 10% of the cluster mass by escape (`f_dt_esc` in `constants.py`; not below `-dtm`), and a non-positive half-mass radius ends the run as `CLUSTER DISSOLVED`. Runs that never reach this regime are unchanged.

## [2.14.3] - 2026-10-26

Results are byte-identical to 2.14.2 for a given seed (all output files; `log.txt` gains a line), except in runs where a ZLK merger of a hierarchical triple would happen after redshift 0 (fix 1), which change from that point on. No such case occurred in the 26 test configurations or in four full runs of compact clusters with ~30-10^4 ZLK mergers each.

### Fixed
1. **ZLK mergers after redshift 0** (`triples.py`). When the ZLK merger time t + t_ZLK of a triple's inner pair fell after the present, the merger was still counted in `N_me` and `N_ZLK` (but not written to `mergers.txt`), the triple was removed, and either the remnant (with its GW kick) was put back in the cluster at once, although the merger had not yet happened, or, if the outer BH stayed bound, the remnant and the outer BH disappeared from the cluster altogether (neither single nor in a binary, while still counted in `N_BH`). Such a merger has not happened by the end of the simulation: the triple is now kept unchanged and examined again at later steps like any other triple. The check comes before any random draw, so runs without such a case are unchanged (`tests/test_zlk_after_today.py`).

### Changed
- **Reason for the end of the run in `log.txt`.** The stops decided inside a time step already printed their reason (`REDSHIFT 0 REACHED`, `CLUSTER DISSOLVED`, `CLUSTER REACHED GALAXY CENTER`, `BH SUBSYSTEM EVAPORATED`), but a run ended by the condition of the main loop said nothing. It now prints `SINGLE BHS REACHED A FRACTION fBH_max = 0.2 OF THE CLUSTER MASS` (the usual end of small, compact clusters, previously easy to mistake for a crash) or `MAXIMUM SIMULATION TIME REACHED` (`-tM`).
- **Merger table written during the run**, like the other tables since 2.14.2. Each merger line ends with the final cluster properties, known only at the end, so the rows are written during the run and the file is then copied once, line by line, appending them (`StreamedRowLog.finish(..., suffix=...)`; same text, checked in `tests/test_streaming.py`). This removes the memory used by the merger rows (e.g. peak memory 1.22 -> 1.07 GB for N = 1e8, r_h = 0.1 pc, with 6.5e5 mergers; run time unchanged).

## [2.14.2] - 2026-10-26

Results are byte-identical to 2.14.1 for a given seed (all output files; checked on 26 configurations up to N = 1e8 and on full runs of the most compact massive clusters).

### Changed
- **Output written during the run.** The evolution, hardening and TDE tables (millions of rows in compact massive clusters) are written to their files in chunks of 131072 rows during the run (`StreamedRowLog` in `arraycache.py`, `flush_records` once per time step) instead of being kept in memory and written at the end, with the same text: memory no longer grows with the number of recorded events. Peak memory of full runs: 4.75 -> 1.18 GB for N = 1e8, r_h = 0.1 pc (which forms a 2.4e5 Msun IMBH and records 6e6 TDEs and 9e6 hardening interactions), 1.11 -> 0.39 GB for N = 10^7.5, r_h = 0.1 pc. The rows go to hidden temporary files (`.evolution.txt.part`, ...) in the results folder, renamed to the output files when the run ends normally, so a run that is interrupted leaves only `.part` files. The rows that can still change are kept until the end (the last hardening row, whose end-of-evolution condition is set afterwards, and the last two evolution rows, of which `write_output` drops one or two depending on how the run ends). The merger rows, which end with the final cluster properties, are still written at the end. Rows of tables switched off (`-Ei 0`, `-Hi 0`, `-Ti 0`) are no longer kept in memory. Checked to give identical files whatever the chunk size (`tests/test_streaming.py`).

### Performance (results unchanged)
1.2-1.3x faster for compact clusters dominated by three-body binaries and BBH encounters (e.g. 148.5 -> 123.6 s for N = 1e7, r_h = 0.1 pc, which forms a ~1350 Msun IMBH; 52.3 -> 40.9 s for a 2e4 Msun seed BH in N = 2e6, r_h = 0.3 pc, n = 4e7 pc^-3), 1.05-1.15x for those dominated by BH-star TDEs (e.g. 594.7 -> 518.1 s for the full run of N = 10^7.5, r_h = 0.1 pc; 1786 -> 1707 s for N = 1e8, r_h = 0.1 pc), unchanged for ordinary clusters (paired timings, the two versions running side by side):
- **Pool of single BHs**: a change of a BH now only marks its block of 128 BHs; the block sums are recomputed when next needed, once per block however many times it changed (e.g. the last block while the BHs of the new three-body binaries are removed). This also removes, from every pool update, the loop over the cumulative sums kept since 2.14.1, which had made clusters dominated by three-body binaries a few percent slower in 2.14.1. Same sums, bit for bit (the same BLAS dot product over the same block contents).
- Cumulative sums in the weighted draws without the `np.cumsum` Python wrapper (`np.add.accumulate`), scalar clamps of the ZLK eccentricity without `np.clip`, and rows appended to the binary and triple arrays with the `np.concatenate` that `np.append` calls (identical values).

## [2.14.1] - 2026-10-26

Dynamics and all output except the column `r_mb` of `tdes.txt` are byte-identical to 2.14.0 for a given seed (checked on 26 configurations up to N = 1e8).

### Fixed
1. **Marginally bound radius of TDE orbits** (`r_mb`, column 14 of `tdes.txt`; output only, not used by the dynamics). The lookup table `Data/x_mb_vec.pkl` measured the orbital angle from the equatorial plane (90 deg = equatorial), while the code passed the inclination measured from the BH spin axis (0 = prograde equatorial), so prograde orbits were given the values of the complementary inclination (e.g. a polar-orbit radius for an equatorial orbit), and every retrograde orbit (inclination > 90 deg, half of the TDEs) fell outside the table and was written as `nan`. The table also contained unconverged points (its root finder returned the initial guess 4 GM/c^2, e.g. for retrograde orbits around rapidly spinning BHs). `r_mb` is now computed exactly: for a Kerr BH the conditions R = R' = 0 of a marginally bound (E = 1) spherical orbit give the axial angular momentum and Carter constant in closed form for each radius, and the radius with the sampled inclination is found by root finding (`x_mb` in `functions.py`; checked against the equatorial limits and an independent solution in `tests/test_marginally_bound.py`). `Data/x_mb_vec.pkl` and its generator `Data/.marginally_bound.py` are removed.

### Performance (results unchanged)
Byte-identical output (26 configurations, including NS, gas, IMBH-seed, TDE-dominated and N = 1e8 clusters); ~1.3x faster for clusters dominated by BH-star TDEs (e.g. 699 -> 530 s for N = 10^7.5, r_h = 0.1 pc; 214 -> 165 s for the first 25 Myr of N = 1e8, r_h = 0.1 pc), unchanged for clusters dominated by three-body binaries, with 20-25% less memory (exactness checked in `tests/test_speedups_2141.py`):
- `r_mb` is computed for all TDEs at once when the output is written, instead of interpolating at every TDE (it is not used during the run).
- **NS spin evolution during TDEs** (~2x faster per NS TDE): the masses of the Euler steps do not depend on the spin, so the NS radii are interpolated for all steps in one call, and the NS spin and ISCO expressions are evaluated inline, sharing the moment of inertia (the same operations in the same order).
- **Pool totals**: the cumulative block sums of each weight family are kept between draws and, after a BH changes, recomputed only from its block on, with the same sequential additions (bit-identical to recomputing them all).
- The TDE and evolution records are stored compactly (8 bytes per value) like the hardening and merger records.

## [2.14.0] - 2026-10-25

Results change with respect to 2.13.1 through the three-body-binary fix (1) and the new default central density (6) when `-N`/`-r` differ from their defaults; fixes 3-5 change only the corresponding output files. The first two groups of performance changes leave results bit-identical; the pool of single BHs and the last group (batched three-body draws, BBH-BBH partner draw, ZLK root) give statistically equivalent results: the same distributions, but for a given seed a different realization than before.

### Fixed
1. **Three-body binary pairing** (`three_body_binary.py`). Since the April 2026 rewrite of `fast_sample_3bodyBinary`, the proposal weights (m^4 for the binary members, m^(5/2) for the third body) were computed but never used: candidates were drawn uniformly, so the pairing followed (m1+m2)^(-1/2) (m1+m2+m3)^(-1/2) and favoured light BHs. The three BHs are now drawn, as distinct BHs, from the intended density p(m1, m2, m3) ~ (m1 m2)^4 m3^(5/2) (m1+m2)^(-1/2) (m1+m2+m3)^(-1/2), with an exact rejection sampler whose mass-dependent bounds keep the acceptance high also when an IMBH or a massive seed BH dominates (checked against the exact distribution in `tests/test_fixes.py`). The heaviest BHs now pair first: e.g. for N = 2e6, r_h = 0.5 pc the mean total mass of merging BBHs rises from ~63 to ~79 Msun.
2. **`-SD 2` (beta spin distribution)** drew spins from an unseeded `np.random.default_rng()`, so runs were not reproducible for a given seed. Spins are now drawn from the seeded global stream (`np.random.beta`).
3. **Hardening file**: when a BBH evolution ended (conditions 2-6), the condition was written to row `i` of the whole log (the binary index) instead of the current row, overwriting the first rows of `hardening.txt`. It is now written to the row of the last interaction.
4. **TDE file**: a whole-binary disruption (type 22) adds two rows (one per BH) but `N_tdeBBHstar` counts one event, and the writer looped over the event counters, so the last rows were not written. All rows are now written.
5. **`outputBHs.pkl`**: `hBH` (number of TDEs per BH) was always an empty list; it now holds one array per snapshot, aligned with `mBH`, `sBH`, `gBH`. The snapshots also contained three spurious zero-mass entries (the placeholder rows of the binary and BH-star arrays), which are no longer included.
6. **Default central density**: `-n` defaulted to 5.3e5 pc^-3 whatever `-N` and `-r`. It now defaults to the Plummer value n = 0.53 N / r_h^3 (unchanged, 5.3e5 pc^-3, for the default N = 1e6, r_h = 1 pc); `-n` still overrides it. The density used is printed at the top of `log.txt`.

### Performance (results unchanged)
Typically 2.5-3x faster for heavy clusters (N >~ 1e7) and ~2x faster wall time for small ones, with byte-identical output for a given seed (checked on 23 configurations, including N = 1e8):
- Weighted draws (`np.random.choice` with `p=`) reuse their cumulative distribution when the weights are unchanged (BBH-single partner, two-body capture candidates), via bit-exact helpers in the new `rapster/fastrandom.py`.
- Poisson draws call `np.random.poisson` directly (same values and random stream as `scipy.stats.poisson.rvs`).
- Removed unused passes over all BHs, memoised the lookback time at the cluster formation redshift, cached the mean separation of star-star binaries, and hoisted x-independent terms out of the ZLK root function.
- Cheaper single-element `delete`/`append` on the BH arrays; mergers and TDEs are accumulated in lists instead of arrays copied at every append.
- The per-step status table no longer builds pandas DataFrames (same text).
- Start-up time 5.6 s -> 1.8 s: the Maxwellian CDF table is built in ~10 ms (identical values), and Matplotlib is imported only for `-plot 1`.
- BH snapshots (`-BOi 1`) are written to a temporary file next to the results instead of being kept in memory (~20 GB of RAM for N = 2.5e7, r_h = 0.4 pc), and streamed into `outputBHs.pkl`, which loads exactly as before.

Further optimizations for compact clusters, where (with fix 1) three-body binaries, BBH-single encounters and BH-star TDEs number in the hundreds of thousands to millions per run (results again byte-identical, checked on 25 configurations up to N = 2.5e7, including IMBH-dominated and TDE-dominated clusters):
- **Weighted draws without sequential cumulative sums.** Every weighted draw from the BHs (BBH-single partner, three-body binary members, two-body capture candidates, BH-star TDEs) used to build `np.cumsum` over all ~1e4-1e5 BHs (~3 ns per BH, the largest single cost). `CumulativeSearch` (in `fastrandom.py`) locates the random number with vectorized block sums instead and certifies, with a rigorous floating-point error bound, that the index is the one the exact cumulative sum gives; only when the random number falls within ~1e-10 of a boundary (essentially never) is the exact sum computed.
- **Powers of the BH masses reused.** `ElementwiseCache` (new `arraycache.py`) keeps mBH**p and exp(p log mBH) between calls and evaluates them only for BHs that are new or changed (exact, since these functions act on each BH independently).
- Three-body sampler: the five weight arrays are handled as one stacked array (fewer NumPy calls), and the most massive BH is zeroed in place instead of copying the arrays.
- Spin evolution during TDE accretion runs in Python floats (it silently switched to slower NumPy-scalar arithmetic after the first step), with repeated powers computed once: ~2x faster, identical values.
- Partner draws skip re-comparing the BH array within one call of `evolve_BBHs`; paired BH-array edits are done in one copy; the mean BBH mass is recomputed only when the binaries change; the ZLK root function is evaluated with Python floats (same IEEE operations); output files are written with a faster formatter (same text); the hardening and merger records are stored compactly (8 bytes per value instead of ~40, i.e. ~1 GB less RAM after 1 Gyr of a compact cluster).

### Performance (statistically equivalent results)
The exact optimizations above are limited by passes over all single BHs at every event. For compact clusters that form IMBHs through repeated mergers, the single BHs are now kept in a pool with O(1) updates and fast weighted draws, and the samplers draw from the same distributions as before by rejection sampling. Every distribution is unchanged, but the random numbers are used differently, so a given seed gives a different (equally probable) realization. Speed-up over the exact version above (ensembles of 16-30 seeds per configuration): 3.0x for N = 1.6e7, r_h = 0.26 pc, n = 5.3e5 pc^-3 (IMBH of ~2000 Msun by 300 Myr); 3.0x for the same cluster at its Plummer density (dominated by ~5e4 BH-star TDEs in 150 Myr); 3.9x for N = 2.5e7, r_h = 0.41 pc (400 Myr); 1.6x for a 2e4 Msun seed BH in N = 2e6, r_h = 0.3 pc, n = 4e7 pc^-3, where the remaining time is spent in the per-encounter work of the BBH evolution (hundreds of BBH-BBH encounters per step) and in the ZLK root finding of triples rather than in drawing BHs. Together with the exact optimizations, these clusters run ~2-5x faster than with the bug fixes alone.
- **Pool of single BHs** (new `rapster/bhpool.py`, class `BHPool`). The four arrays `mBH`, `sBH`, `gBH`, `hBH` (copied whenever a BH was added or removed) are replaced by one object with spare capacity: a BH is added at the end and removed by moving the last BH into its slot. For every weight used by a sampler (m^4, m^(5/2), m^(1/3), ...) the pool stores the weight of each BH and the sums over blocks of 128 BHs, updated when a BH changes; a weighted draw locates the random number among the block sums and then within one block (a few microseconds for up to ~1e5 BHs). The functions that took `mBH, sBH, gBH, hBH` now take the pool `BH` (`state['BH']`; masses, spins, generations and TDE counts are `BH.m`, `BH.s`, `BH.g`, `BH.h`).
- **Three-body binaries** (`sample_3bodyBinary`): same regions and bounds as `fast_sample_3bodyBinary`, with the BHs of a region proposed independently from the pool (proposals that repeat a BH are rejected). If very few BHs carry almost all the weight, so that most proposals would repeat a BH, the exact array sampler `fast_sample_3bodyBinary` is used.
- **BBH-single partner** (`sample_BBH_partner`): rejection from m12^(1/5) (m12 m^(3/2) + m^(5/2)) or m12 m^(17/10) + m^(27/10), which bound the weight (m12 + m) m^(3/2) / sqrt(m12^(-2/5) + m^(-2/5)) (acceptance >= ~0.4).
- **Two-body captures** (`sample_2capture`): the distribution of the previous sampler (pairs drawn without replacement with p ~ m^(2/7), accepted with probability ~ (m1 + m2)^(10/7)) by rejection from m1^(12/7) m2^(2/7) + m1^(2/7) m2^(12/7) (acceptance >= 0.74 (1 - p_max)).
- **TDEs** (`draw_TDE_BH`): the weight (m_star + m) m^(1/3) is an exact mixture of m^(1/3) and m^(4/3). Exchanges draw from the BH masses (and uniformly) the same way. The mean single-BH mass and sum(m^(5/2)) (relaxation factor) come from the pool sums.
- **Spin evolution during TDE accretion** (`spin_after_accretion` in `compact_accretion.py`): for a BH whose mass grows by at most 2% (all TDEs onto IMBHs and most onto stellar BHs), the final spin is integrated with fourth-order Runge-Kutta steps in ln M instead of the ~100 Euler steps of `evolve_spin_during_accretion` (~10x faster). It reproduces the Euler loop, including its handling of the Thorne limit and of retrograde disks that spin the BH down to zero, to < 1e-6 in the spin; NSs and larger mass growth use the Euler loop as before.
- Statistical validation against the exact version (106 seeds per version in five ensembles of the four clusters above): the distributions over seeds of the numbers of mergers (by channel), three-body binaries, captures, ejections, exchanges and TDEs, of the maximum BH mass at several times (IMBH growth) and of the highest remnant generation, and the merger (m1, m2, q, chi_eff, remnant spin and generation, kick, merger time) and TDE properties agree (Mann-Whitney and Kolmogorov-Smirnov tests).
- These samplers replace, for the draws from the single BHs, the exact block-sum draws and cached powers of the previous group, which remain in use only in the exact three-body sampler (fallback above).

### Performance (results identical to the pool version above)
Further optimizations that leave the output byte-identical for a given seed (checked on the same 25 configurations as above, including NS, gas, IMBH-seed and TDE-dominated clusters): ~1.4-1.6x faster for small and medium clusters (the default run takes 1.2 s instead of 1.8 s) and ~1.1-1.2x for compact ones (e.g. 14.8 -> 12.1 s for N = 1.6e7, r_h = 0.26 pc, 150 Myr; 77.5 -> 66.2 s with a 2e4 Msun seed BH).
- **Start-up**: `scipy.stats` (~0.6 s to import) is no longer imported: NS natal kicks are drawn by `maxwell_draws` (`fastrandom.py`) as sqrt(chi2(3)) times the scale, exactly as `scipy.stats.maxwell.rvs` does (same values, same random numbers). `scipy.stats` and `pandas` are imported only if needed (Poisson fallback for invalid rates, status tables wider than 80 characters).
- **NS spin evolution during TDEs** (~4x faster): in the NS branch of `evolve_spin_during_accretion`, `f_from_chi`, `f_kepler`, `chi_kepler` and the NS ISCO energy and angular momentum are evaluated with Python floats (`_ns_spin_state`, `_ns_E_J_isco`: the same operations in the same order), and the ISCO quantities once per step instead of twice (E_isco and J_isco evaluated the same function).
- **BBH evolution** (`evolve_BBHs`): the escape velocity, lookback time at cluster formation, velocity factors of the interaction rates and Maxwellian dispersions are computed once per call; the interaction rates are written out with the operations of `Rate_int`; the BBH-BBH partner draw copies only the two needed columns; the partner sampler evaluates its candidates in Python floats.
- `T_GW` evaluates ordinary scalar inputs with Python floats (same pow and IEEE operations); Maxwellian velocity draws and the EoS mass-radius relation call the compiled interpolation of `np.interp` directly; the ZLK root (`find_eMAX`) calls MINPACK's `hybrd` directly with the parameters `scipy.optimize.root` passes to it; the TDE marginally bound radius calls the scalar function behind `np.vectorize`.
- Pool draws reuse the cumulative weights within a block while the block is unchanged, and a family's total is the last of its cumulative block sums (the same sequential sum as before).

### Performance (statistically equivalent results, second round)
The same physics and distributions, with a different use of the random numbers (validated as below). Speed-up over the previous group (ensembles of 12-30 seeds per cluster, same seeds for both versions): 1.34x for a 2e4 Msun seed BH in N = 2e6, r_h = 0.3 pc, n = 4e7 pc^-3 (100 Myr); 1.11x for N = 2.5e7, r_h = 0.41 pc (400 Myr); 1.04-1.05x for N = 1.6e7, r_h = 0.26 pc at n = 5.3e5 pc^-3 and at its Plummer density. In these compact clusters the run time is now mostly the fixed Python cost of each of the ~1e5 BBH encounters per run, rather than any single routine.
- **Three-body binaries of one step** (`three_body_binary`): the BHs bound into binaries are removed from the pool at the end of the step instead of after each binary, and excluded from the later draws of the step by rejection (`sample_3bodyBinary(BH, exclude=...)`), which gives the same distribution over the remaining BHs as removing them first. The pool's sums then stay valid for the whole step. The excluded BHs are removed early when the heaviest single BH is taken (it defines the regions of the sampler) or when 30 proposals in a row hit excluded BHs.
- **BBH-BBH encounters** (`evolve_BBHs`): the other BBH (probability ~ (m1 + m2) a) is located directly in the cumulative weights of all BBHs, with the current one at weight zero, instead of copying the arrays without it, normalizing and searching the drawn semimajor axis.
- **Binary-single GW captures**: the three intermediate states are evaluated one by one with Python floats instead of three-element arrays (same expressions and random numbers).
- **ZLK maximum eccentricity** (`find_eMAX`): the root of DW(x) is found by `_zlk_smallest_root`. With y = sqrt(x), 4 B^2 y^2 DW is a quartic in y with two positive roots or none (Descartes' rule); when the local minimum of the quartic is negative, the smaller root is found by safeguarded Newton iterations and polished on DW itself. It is the root that `scipy.optimize.root` started at x = 1e-10 converges to: for 39,596 triples from compact-cluster runs, e_max agrees to <= 1.2e-13 (and is identical in 86% of the cases), ~3x faster. Without a positive root (2% of the triples, where the MINPACK solver stops without converging), the MINPACK solver is used as before.
- Validation against the previous group: (1) ensembles of 30, 16, 24 and 12 seeds of the four clusters above: the per-run numbers of mergers (by channel), three-body binaries, captures, ejections, exchanges, ZLK mergers and TDEs, the maximum BH mass at several times and the highest remnant generation agree (Mann-Whitney and Kolmogorov-Smirnov tests; the IMBH growth varies strongly from seed to seed); (2) one step of binary formation and BBH evolution repeated 1500 times from the same cluster state (a compact cluster with a 340 Msun BH, and an IMBH-seed cluster with ~270 three-body binaries per step): all event counts and the mean masses and semimajor axes of the binaries agree to within the statistical errors (~0.1% for the binary masses).

## [2.13.0] - 2026-10-13

### Added
- Extended neutron-star formation times (`-NSt` / `--ns_formation_time_model`, default `0`). NS masses are still set by `-NS 1/2/3`; `-NSt` sets when each NS forms:
  - `0`: all NSs form at the BH formation time `tBH_form` (previous behaviour).
  - `1`: formation times drawn from the COMPAS distribution p(t_form), independent of NS mass.
  - `2`: formation times drawn from p(t_form | m_NS), in the 0.05 Msun NS-mass bin nearest to each NS mass; heavier NSs form earlier (median t_form = 30 Myr at 1.28 Msun, 19 Myr at 1.4 Msun, 13 Myr above 1.8 Msun).
  For `-NSt 1/2`, NS masses, natal kicks and formation times are drawn at initialization; each NS is formed in the main loop once t >= t_form (`form_neutron_stars` in `cluster_evolution.py`) and is retained if its kick is below the escape velocity at that time, v_esc(M_cl + M_gas, r_h). Since the cluster loses mass and expands before most NSs form, fewer NSs are retained than with `-NSt 0` (e.g. N = 2e5, `-wK 20`: 112 NSs with `-NSt 0`, 59 with `-NSt 1`, 64 with `-NSt 2`). An NS joins the cluster at the end of the step in which t_form is reached, i.e. at most one time-step late. The numbers of NSs formed and retained are printed to `log.txt` at the end of the run. Usage: `python -m rapster.run_cluster -NS 2 -NSt 2`.
- NS formation-time table `Data/NS_formation.npz`: quantiles of log10(t_form) for all NSs and in each NS-mass bin, built from 27,454,686 NSs of a COMPAS (v03.29.03) population of 1e8 binaries at Z = 0.0142 (Kroupa primary masses in 5-150 Msun, flat mass ratios, log-flat separations, Fryer et al. 2012 delayed remnants, maximum NS mass 2.5 Msun). NS masses span 1.26-2.50 Msun; 5%, 50% and 95% of NSs form by 11, 25 and 52 Myr, and 0.06% after 1 Gyr. The table sets only the shape of the formation-time distribution; the number of NSs is still set by the Kroupa IMF between 8 and 18 Msun.
- `rapster/ns_formation.py`: loader and sampler for the NS formation-time table.
- `tools/make_ns_formation_table.py`: builds `Data/NS_formation.npz` from a population-synthesis sample of NS masses and formation times. Not part of the installed package.
- `tests/`: tests for the NS formation-time sampler, the NS initialization and NS formation in the main loop. Run from the repository root with `python3 tests/test_ns_formation.py`, `python3 tests/test_ns_initialization.py` and `python3 tests/test_ns_main_loop.py`. `tests/test_ns_physics.py` checks that the number of retained NSs in a full run agrees with the analytic expectation sum_i P_Maxwell(v < v_esc(t_i)), and that with `-NSt 2` the sampled formation times follow the COMPAS distribution in each mass bin. `tools/plot_ns_formation_check.py` produces diagnostic figures of the sampled NS masses and formation times and of NS retention.

### Changed
- BH formation time `tBH_form` (in `constants.py`) is now 10 Myr (was 3.5 Myr): all stellar-mass BHs are assumed to have formed by 10 Myr after cluster formation, when the BH subsystem is activated. This changes all runs with respect to earlier versions. For gas-free runs (`-sfe 1`, default) the only effect is the later activation of the BH subsystem. For runs with residual gas (`-sfe < 1`), less gas remains at BH formation, M_gas = M_gas0 exp(-tBH_form/t_ge), which lowers the escape velocity used for natal-kick retention of BHs (and of NSs with `-NSt 0`).
- If no compact objects are present when the BH subsystem would activate, or if they have all been lost, the run no longer stops with `BH SUBSYSTEM EVAPORATED` while NSs are still to form (`-NSt 1/2`); the subsystem activates once they form.
- Regenerated `Example/Results_Test/` with this version. The previous reference outputs predated the 2.12.0 physics changes (multimass relaxation factor, Coulomb logarithms, core-collapse time, Jacobi radius) and no longer matched 2.12.x; with tBH_form = 3.5 Myr the default run of this version is byte-identical to 2.12.2.
- NS mass sampling moved to the helper `_draw_ns_masses` in `cluster_evolution.py`. With `-NSt 0`, random numbers are drawn in the same order as before, so for a fixed `tBH_form` results are byte-identical to version 2.12.2.

### Known limitations
- The COMPAS sample does not include NSs from the companions of binaries disrupted by the first supernova, which are less massive and form NSs later; the table therefore under-represents late-forming NSs.
- NS natal kicks are drawn from a single Maxwellian for all NSs; the lower kicks of electron-capture and ultra-stripped supernovae (30 km/s in the COMPAS model), which dominate the late (~Gyr) NSs, are not modelled.

## [2.12.0] - 2026-10-10

### Added
- Validate external BH input archives: require an existing `.npz` file with a one-dimensional `mBH_ini` array of finite, positive real masses in solar masses. Empty arrays remain supported.
- Validate CLI numeric ranges and categorical options before simulation setup.
- Escape-velocity prefactor (`-fesc` / `--escape_velocity_factor`, default `2.0`). The escape velocity is v_esc = f*sqrt(<v_star^2> + <v_BH^2>), with <v^2> = 0.4 G M / r. It applies to natal-kick retention of BHs and NSs, merger-remnant retention, and dynamical ejection of single BHs and BBHs after BBH-BH encounters. `f = 2` (default) is the mass-weighted rms escape speed and reproduces previous results exactly. `f = sqrt(10)` gives v_esc = sqrt(4 G M_cl / r_h), the estimate used by Mai, Kremer & Kiroglu (2025) for the CMC colossus model. The value used is printed to `log.txt`. Usage: `python -m rapster.run_cluster -fesc 3.16227766`.
- BH-to-star temperature-ratio prefactor (`-cxi` / `--bh_temperature_prefactor`, default `1.0`). Breen & Heggie (2013) give the ratio only as a scaling, xi ~ q^(3/5) Q^(2/5) (ln Lambda_BH / ln Lambda)^(-2/5), with q = <m_BH>/<m> and Q = M_BH/M_cl; `c_xi` is its order-unity prefactor. Since r_h,BH = Q q r_h / xi, the BH half-mass radius scales as 1/c_xi, and c_xi also enters the BH core radius. `c_xi = 2` reproduces the CMC colossus model (Mai, Kremer & Kiroglu 2025) to ~10% in r_h, N_BH and the number of BBH mergers at 12 Gyr (with `-fesc 3.16227766`). Usage: `python -m rapster.run_cluster -cxi 2`.
- Constant `a1_psi = 1.47` in `constants.py`, the coefficient of the multimass relaxation factor (see Changed).

### Changed
- Regenerated `Example/Results_Test/` from the current default run and made `Example/tutorial.ipynb` discover results relative to the repository with snapshot indices adapted to the available BH snapshots.
- Align the external BH input default filename with the README (`input_BHs.npz`) and update README dependency versions, CLI defaults, example paths, output formats, and units.
- Escape velocity is now computed in one place: `v_esc_cl(v_star, vBH)` for retention and ejection, and `v_esc(Mcl, rh)` for natal kicks, both in `functions.py` and both scaled by the module-level prefactor `F_ESC` (set once via `set_escape_factor()`). This replaces seven hard-coded `2 * np.sqrt(v_star**2 + vBH**2)` expressions in `binary_evolution.py`, `triples.py`, and `two_body_capture.py`.
- The `v_esc` column of the mergers file (column 25) and of the evolution file (column 56) now records the threshold actually used, f*sqrt(<v_star^2> + <v_BH^2>). It previously recorded `2*v_star`, omitting the BH term, so values differ slightly from older outputs even at `f = 2`. The `v_escBH` column (escape velocity from the BH subsystem) is unchanged.
- Jacobi radius now uses the isothermal-potential (flat rotation curve) value, r_J = (G M_cl R_g^2 / 2 v_g^2)^(1/3), consistent with the isothermal galaxy assumed elsewhere (circular velocity v_g, dynamical-friction timescale). It previously used the point-mass value with factor 3, which underestimated r_J by a factor (3/2)^(1/3) = 1.14. A larger r_J lowers the escape rate xi_e = xi_e0 exp(10 r_h/r_J) and hence tidal mass loss; the effect compounds over time for tidally limited clusters (e.g. a 1.8e5 Msun cluster at R_g = 2 kpc retains ~15% more mass at 2 Gyr and ~2x more at 4 Gyr). Results for clusters at large R_g, or with r_h << r_J, are essentially unchanged. Runs made with earlier versions used the factor 3.
- Dynamical friction now integrates Eq. (7) of Gnedin, Ostriker & Tremaine (2014), dR_g^2/dt = -R_g^2/t_df, i.e. dR_g/dt = -R_g/(2 t_df). It previously used dR_g/dt = -R_g/t_df, which made the orbital decay a factor of 2 faster than the cited prescription. The dynamical-friction timescale itself is unchanged and follows their Eq. (8), t_df = 0.45 Gyr (R_g/kpc)^2 (v_g/km s^-1) (M_cl/1e5 Msun)^-1 f_eps, with ln Lambda = 5.8 and eccentricity factor f_eps = 0.5. Example: a 1e6 Msun cluster at R_g = 1 kpc moves inward by ~70 pc in 1 Gyr instead of ~130 pc. Runs made with earlier versions used the faster decay.
- Multimass relaxation factor: psi = 1 + a1 f_BH/0.01 with a1 = 1.47 (Antonini & Gieles 2020, Eq. 12), replacing the equipartition form psi = 1 + S with S = Q q^(3/2). The old form assumes energy equipartition, which fails for Spitzer-unstable BH populations (S > 0.16); it overestimated psi by ~3x and grew without bound as the mean stellar mass decreased, so clusters over-expanded and lost too much mass. The Spitzer parameter S is no longer overwritten in the equipartition branch and is now always output as Q q^(3/2). Example (colossus initial conditions): r_h at 12 Gyr is 6.95 pc instead of 11.9 pc (CMC: 6.44 pc).
- Coulomb logarithms: ln Lambda = ln(e + 0.02 N) for the cluster, with N = M_cl/<m> the current number of stars (was fixed at 10), and ln Lambda_BH = ln(e + 0.02 N_BH) for the BH subsystem (was 1), following Breen & Heggie (2013). The e keeps both >= 1 for small N. The cluster form is also used in the initial relaxation time (was ln(0.02 N)).
- Core-collapse time of the BH subsystem is now set by BH mass segregation, t_cc = k_cc (<m>/<m_BH>) t_rh,0, with t_rh,0 the initial single-mass (psi = 1) relaxation time, <m_BH> the mean mass of the retained BHs, and k_cc = 3.21 (Spitzer 1969). It previously used t_rh,0 with psi_0 = <m^5/2>/<m>^5/2 over the full IMF (0.08-150 Msun), dominated by stars that die within ~3 Myr, which made core collapse too early. Example (colossus initial conditions): t_cc = 150 Myr instead of 29 Myr; the cumulative BBH merger history then matches the CMC model from 0.3 Gyr on. The IMF-based estimate is kept when no BHs are retained.

- Performance: substantial speedups across the hot paths — vectorized `IMF_kroupa` (hybrid scalar + `np.select` array path); a faster, bit-identical TDE spin integrator (`evolve_spin_during_accretion`, formerly `evolve_v2`); list-accumulation of the evolution and hardening arrays instead of `np.append` (O(N^2) → O(N)); removal of `np.vectorize` from the remnant-mass functions in favor of their vectorized array branch; and `np.clip` replaced with `min`/`max` in the `compact_accretion` hot path.
- BH/NS spins are now clipped to the Thorne limit χ ≤ 0.998 via a new `THORNE_SPIN_LIMIT` constant (default `0.998`) in `constants.py`, applied during accretion spin-up.
- Escape velocity now accounts for the residual gas mass: `M_gas` is included in the cluster potential when computing `v_esc`, and the gas mass at the time of BH formation is used when comparing natal SN kicks against the escape velocity.
- TDE stellar-mass sampling now includes a rate-dependent mass factor in p(m_star | TDE), and pericenter (`r_p`) sampling is unified across single–BBH interactions (with or without a μTDE).
- Poisson rate parameter (μ = dt/t_channel) is now capped for all interaction channels to prevent overflow in `poisson.rvs`.

### Fixed
- Corrected a sign error in the average-mass evolution: the stellar mass-loss factor was `(t/t_sev)^ν_sev` and is now correctly `(t/t_sev)^(−ν_sev)`. This affects the cluster's average-mass evolution and everything downstream of it.
- Corrected pericenter sampling: `r_p` is now sampled with probability ∝ `r_p` in the gravitational-focusing regime (for both single–BBH and `N_IMS−1` cases), rather than uniformly.
- Fixed initialization of NS masses when the bimodal distribution (`-NS 2`) is selected.
- Fixed redshift–lookback interpolation: added range checks when interpolating `z_merge` for 2-body capture, 3-body GW, and ejected mergers, and handled negative lookback times.
- Fixed the unconditional definition of `M_gas_BHform` in the gas/accretion path.
- Fixed numerous index/channel bugs in `cluster_evolution.py`, `binary_evolution.py`, `exchanges.py`, `triples.py`, and `tidal_disruptions.py` — including the pair–pair and ex1/ex2 channels, `k1`/`k2`/`kss`/`kp` index handling when creating pairs, a non-existent third BH in the BH subcluster, `a1`/`a2` semimajor-axis sampling, and correct unpacking of binary properties (m, s, g, h) after a TDE.
- Fixed TDE bookkeeping during star–star–BH and BH–star–BH interactions.
- Fixed IMF integration and TDE plotting (scipy `quad`), and ensured mergers in `triples.py` occur by z = 0.
- Renamed `type` variable to `tde_type` in `tidal_disruptions.py` and `cluster_evolution.py` to avoid shadowing Python's builtin `type()`.
- Populated `__init__.py` with public API exports. Users can now do `from rapster import initialize_cluster, analyze_cluster, generate_all_plots` etc. CLI-specific functions (`parse_args`, `main`) remain in `run_cluster.py`.
- Replaced `np.transpose(array)[:][i]` with `array[:, i]` across `cluster_evolution.py` (15 instances), `binary_evolution.py` (4 instances), and `exchanges.py` (3 instances). Standard NumPy column indexing idiom — more readable and avoids unnecessary transpose.
- Replaced all 10 bare `except:` clauses in `cluster_evolution.py` with `except Exception:`. Bare `except:` catches everything including `KeyboardInterrupt` and `SystemExit`, which means Ctrl-C could not stop the simulation and errors were silently ignored. `except Exception:` still handles expected errors (e.g., `ValueError`, `ZeroDivisionError` from empty arrays or zero rates) but allows Ctrl-C and system exits to propagate normally.
